FUNDAMENTOS DE SERVICIOS WEB

El mismo dato, dos enfoques.

REST es un estilo arquitectónico. SOAP es un protocolo de mensajería basado en XML.

REST · ENDPOINT EJECUTABLE

Un recurso identificado por su URL

GET /api/productos/1
Accept: application/json

HTTP/1.1 200 OK
{"id":1,"nombre":"Arduino UNO",
 "precio":75,"stock":8}

En esta API elegimos JSON. REST también permite otras representaciones.

SOAP · EJEMPLO ILUSTRATIVO

Una operación dentro de un mensaje

<soap:Envelope
 xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/"
 xmlns:t="urn:tienda">
  <soap:Body>
    <t:ConsultarProducto>
      <t:id>1</t:id>
    </t:ConsultarProducto>
  </soap:Body>
</soap:Envelope>

Este XML ilustra SOAP 1.1. El servicio que construimos y ejecutamos en el taller es REST.

Ejecuta estos comandos en PowerShell desde la carpeta del proyecto. Detén primero el servidor local con Ctrl+C. La primera ejecución en Docker usa su propio volumen de datos; no copia automáticamente el catálogo local.

Un contenedor comparte el kernel del entorno que lo ejecuta. Una máquina virtual incluye su propio sistema operativo. Docker Desktop proporciona el entorno Linux en Windows.
